What changed since v0.2.1 (0.2.2 was never released). The
[README](https://github.com/tome-vtt/silk-installer/blob/v0.2.3/README.md) and
[theme API](https://github.com/tome-vtt/silk-installer/blob/v0.2.3/docs/theme-api.md) describe each feature in full.

## New

- **Silk Installer**: Silk Setup is now Silk Installer, in the docs and the stub's product name. The
  repository is public, so downloading a release needs no token; the README gives the plain download
  links. (SILK-S82-T1, SILK-S82-T2)
- **WebView2 please-wait window**: while the WebView2 bootstrapper downloads and installs the
  runtime, which shows no window of its own, the installer shows a small native please-wait window
  that stays on top and cannot be closed. (SILK-S27-T1, SILK-S48-T1)
- **Programs that keep running**: a process a `[[run]]` program starts with
  `CREATE_BREAKAWAY_FROM_JOB` now keeps running after the program ends, and a cancel leaves it
  running. (SILK-S40-T1)

## Fixes

- **Restart after an elevated install**: when another account answers the UAC prompt, `silk.reboot`
  registers the relaunch, and removes it again, in the starting user's registry hive rather than the
  elevated account's. An installer started already elevated registers it for its own session's user,
  for per-machine installs only. (SILK-S31-T1, SILK-S25-T1, SILK-S51-T1)
- **`silk.openUrl`** opens the browser unelevated, as the signed-in user. It now rejects an address
  holding a `"` or ending in a `\`, and rejects when there is no desktop shell to open it.
  (SILK-S29-T1, SILK-S49-T1, SILK-S51-T1)
- **Waiting for `[[run]]` programs**: once a program exits, the installer waits up to 5 seconds for
  the processes it started, so none holds a file the installer then deletes or rolls back. A talk
  program's `exit` event can therefore come up to 5 seconds after it exits. (SILK-S55-T1,
  SILK-S63-T1)
- **Cancelling a talk program**: a cancel ends the program's whole job and closes its stdin, and no
  longer hangs when a process outside the job holds its input or output pipe open, or a theme answer
  is stuck writing. (SILK-S39-T1, SILK-S58-T1, SILK-S62-T1, SILK-S64-T1, SILK-S78-T1)
- **Rolling back a failed install**: a failed fresh install removes its shortcuts, firewall rules and
  Installed Apps entry, and writes no `install.log`. A failed upgrade keeps the previous version's
  firewall rules and registration. (SILK-S18-T1, SILK-S49-T1, SILK-S50-T1, SILK-S55-T1, SILK-S59-T1,
  SILK-S65-T1)
- **`silk build`** checks `{payload}` paths the same way the installer matches them. (SILK-S25-T1)

## Hardening

- Updated `zip` to 9.0.5 for RUSTSEC-2026-0367, RUSTSEC-2026-0368 and RUSTSEC-2026-0369, and refreshed
  the other Cargo dependencies. (SILK-S13-T1, SILK-S44-T1, SILK-S44-T2, SILK-S44-T4, SILK-S44-T6)
- Workflows are checked by actionlint, with a pinned shellcheck, and zizmor. Pull requests from forks
  run on GitHub-hosted runners, never the self-hosted ones, and a test keeps them there.
  (SILK-S10-T1, SILK-S46-T1, SILK-S52-T1, SILK-S52-T2, SILK-S79-T1, SILK-S82-T1, SILK-S85-T1)

## Maintenance

- The docs say that a cancel or a later failure cannot undo a before-install program that succeeded,
  so such a script should recover when the installer runs again. (SILK-S26-T1)
- CI's Windows job runs the theme API and workflow-lint tests, and new tests cover the theme side of
  `silk.write`, `silk.openUrl` and their events. (SILK-S30-T1, SILK-S34-T1, SILK-S47-T1, SILK-S60-T1)
- The gate and complexity checks leave `docs/` out, and gate paths select nested sources again.
  (SILK-S53-T1, SILK-S61-T1, SILK-S62-T1, SILK-S64-T2, SILK-S80-T1)
- The agent instructions were clarified. (SILK-S87-T1)
