What changed since v0.2.1 (0.2.2 was never released). The
[README](https://github.com/tome-vtt/silk-installer/blob/v0.2.3/README.md) and
[theme API](https://github.com/tome-vtt/silk-installer/blob/v0.2.3/docs/theme-api.md) describe each feature in full.

## New

- **Silk Installer**: Silk Setup is now Silk Installer, in the docs and the stub's product name. The
  repository is public, so downloading a release needs no token. (SILK-S82-T1, SILK-S82-T2)
- **WebView2 please-wait window**: while the WebView2 bootstrapper installs the runtime, the
  installer shows a small native please-wait window that stays on top and cannot be closed.
  (SILK-S27-T1, SILK-S48-T1)
- **Programs that keep running**: a process a `[[run]]` program starts with
  `CREATE_BREAKAWAY_FROM_JOB` now keeps running after the program ends, and a cancel leaves it
  running. (SILK-S40-T1)

## Fixes

- **The signed-in user's registry when another account elevates**: `silk.reboot` registers its
  relaunch, and an elevated uninstall deletes `remove_registry_value`'s HKCU keys, in the signed-in
  user's hive rather than the elevated account's. (SILK-S31-T1, SILK-S25-T1, SILK-S29-T1, SILK-S51-T1)
- **`silk.openUrl`** opens the browser unelevated, as the signed-in user, and always quotes the
  address. It now rejects an address holding a `"` or ending in a `\`, and rejects when there is no
  desktop shell to open it. (SILK-S29-T1, SILK-S49-T1, SILK-S51-T1)
- **Waiting for `[[run]]` programs**: once a program exits, the installer waits up to 5 seconds for
  the processes it started, so none holds a file the installer then deletes or rolls back. A talk
  program's `exit` event can therefore come up to 5 seconds after it exits. (SILK-S55-T1,
  SILK-S63-T1)
- **Cancelling a talk program**: a cancel ends the program's whole job and closes its stdin, and no
  longer hangs on a pipe a process outside the job holds open. (SILK-S39-T1, SILK-S56-T1,
  SILK-S58-T1, SILK-S62-T1, SILK-S64-T1, SILK-S78-T1)
- **Rolling back a failed install**: a failed install or upgrade removes the shortcuts, firewall
  rules and Installed Apps entry it newly added, and a failed add keeps the previous version's
  firewall rules. A failed upgrade keeps the previous version recorded, so a silent rerun of the same
  version tries again; a failed fresh install writes no `install.log`. (SILK-S18-T1, SILK-S49-T1,
  SILK-S50-T1, SILK-S54-T1, SILK-S55-T1, SILK-S59-T1, SILK-S65-T1)
- **`silk build`** checks `{payload}` paths the same way the installer matches them. (SILK-S25-T1)

## Hardening

  the other Cargo dependencies. (SILK-S13-T1, SILK-S44-T1, SILK-S44-T2, SILK-S44-T4, SILK-S44-T6)
- Workflows are linted by actionlint, with a pinned shellcheck, and zizmor, and pull requests from
  forks never reach the self-hosted runners. (SILK-S10-T1, SILK-S46-T1, SILK-S52-T1, SILK-S52-T2,
  SILK-S53-T1, SILK-S79-T1, SILK-S82-T1, SILK-S85-T1)

  leave `docs/` out. (SILK-S30-T1, SILK-S34-T1, SILK-S47-T1, SILK-S60-T1, SILK-S61-T1, SILK-S64-T2,
  SILK-S80-T1)
